# IMPLEMENTATION PLAN — ArenaScrim

> **สถานะ:** ฉบับที่ 2 (เขียนใหม่ตาม D-08..D-40, 10 ต.ค. 2026)
> **สถานะ (10 ต.ค. 2026):** ระยะที่ 0, 1, 2 เสร็จและอยู่ในโปรเจกต์หลักแล้ว · ระยะที่ 3 และ 4 (P4-1..P4-5) **เสร็จในสำเนาทดสอบ** (85/85 PASS) · **เหลือ P4-6:** ย้ายโค้ดเข้าโปรเจกต์หลัก + รัน migration กับ DB จริง — รออนุมัติ (D-21, I-06)
> **ตั้งแต่ระยะที่ 3:** งานที่ต้องใช้ schema ใหม่ทำในสำเนาทดสอบ (`ArenaScrim_test`) เท่านั้น โปรเจกต์หลักจะได้รับโค้ดใหม่พร้อมกับการรัน migration กับ DB จริงที่ได้รับอนุมัติ
> อ้างอิง: `docs/PROJECT_SCOPE.md`, `docs/DECISIONS.md`, `docs/ARCHITECTURE.md`, `docs/TEST_PLAN.md`

## หลักการจัดลำดับ

1. **ทดสอบก่อนแก้** (กลุ่ม A) เพื่อให้มี baseline สำหรับตรวจ regression
2. งานที่**ไม่เปลี่ยน schema** มาก่อน (กลุ่ม B, E2, E3 ส่วนไฟล์) แล้วจึงทำงานที่เปลี่ยน schema (C3, C4, E4, E3 ส่วนคอลัมน์) โดยรวมเป็น migration ชุดเดียว
3. C4 ขึ้นกับ C3 เพราะการรับคำขอต้องสร้างซีรีส์ (D-19)
4. ทุกระยะจบด้วยการรัน regression กลุ่ม A และอัปเดตเอกสาร (CLAUDE.md กฎข้อ 10)
5. ทุกงานพัฒนาและทดสอบในสำเนาโปรเจกต์ก่อน แล้วจึงนำการแก้ไขโค้ดเข้าโปรเจกต์หลัก **ห้ามเขียนข้อมูลลง DB จริง** ยกเว้นการรัน migration ที่ได้รับอนุมัติตาม D-21

## ความเสี่ยงหลัก

| ความเสี่ยง | การลดความเสี่ยง |
|---|---|
| ข้อมูลเดิมหายระหว่าง migration | สำรองก่อน · ทดลองบน DB ทดสอบ · ตรวจจำนวนแถว · มีแผน rollback |
| ฟอนต์ไทยใน dompdf แสดงผลผิด | ทดสอบ PDF ภาษาไทยเป็นงานแรกของ P2-6 |
