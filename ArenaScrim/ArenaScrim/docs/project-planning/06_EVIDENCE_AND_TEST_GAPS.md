## 3. การทดสอบที่ยังไม่ได้ทำ (Test Gaps)

### 3.1 Flow ที่เขียนลง DB — ยังไม่ทดสอบเลย (ความเสี่ยงสูงสุด)

การแก้ไขรอบก่อนเปลี่ยนวิธีส่งข้อมูลของ**ทุก action** (GET → POST + CSRF) จึงต้องทดสอบซ้ำทั้งหมด

| Gap | Flow | เหตุผลที่สำคัญ |
|---|---|---|
| TG-01 | สมัคร → ล็อกอิน (สำเร็จ) | flow เข้าระบบเปลี่ยน (เพิ่ม `functions.php` ใน `login.php`/`register.php`) |
| TG-02 | สร้าง / แก้ไข / ยุบทีม | ยุบทีมเปลี่ยนเป็น `post_button` |
| TG-03 | เพิ่ม / แก้ข้อมูล / ลบสมาชิก | เพิ่ม whitelist ตำแหน่ง และลบผ่าน POST |

| TG-05 | โพสต์ / ปิด / ลบประกาศ Scrim | เปลี่ยน `post_id` เป็นรับจาก POST และเพิ่ม whitelist แรงก์ |

## 4. วิธีทดสอบที่ปลอดภัย (PROPOSAL — รออนุมัติ Q-15 ก่อนดำเนินการ)

เพื่อไม่ให้กระทบข้อมูลจริงใน `arenascrim_db` เสนอทางเลือกตามลำดับความปลอดภัย:

**ทางเลือก A — ฐานข้อมูลและสำเนาโปรเจกต์สำหรับทดสอบ (แนะนำ)**
1. `mysqldump arenascrim_db > backup_YYYYMMDD.sql` เพื่อสำรองข้อมูลไว้ก่อน (อ่านอย่างเดียว)
2. สร้าง `arenascrim_test` แล้ว import `database/arenascrim_db.sql`
3. คัดลอกโปรเจกต์ไปยังโฟลเดอร์แยก เช่น `htdocs/ArenaScrim_test/` แล้วแก้ `config/db.php` **ในสำเนาเท่านั้น** ให้ชี้ไปที่ `arenascrim_test`
4. สร้างบัญชีทดสอบอย่างน้อย 3 บัญชี: admin, หัวหน้าทีม A, หัวหน้าทีม B (สำหรับ TG-09)
5. รัน TG-01 ถึง TG-19 พร้อมเก็บภาพหน้าจอและผล query ยืนยัน
6. ลบ `arenascrim_test` และโฟลเดอร์สำเนาเมื่อเสร็จ

**ทางเลือก B — ทดสอบบน DB จริงโดยสำรองไว้ก่อน**
สำรองด้วย `mysqldump` → ทดสอบ → restore กลับ ความเสี่ยงคือถ้า restore ผิดพลาด ข้อมูล 12 แมตช์เดิมจะเสียหาย

**ทางเลือก C — ทดสอบด้วยมือบนเบราว์เซอร์โดยเจ้าของโครงการเอง**
ใช้ checklist ใน `AUDIT_REPORT.md` §7 และ `05_ACCEPTANCE_CRITERIA_DRAFT.md`

ไม่ว่าเลือกทางใด ผลที่ได้ควรนำไปเติมคอลัมน์สถานะใน `05_ACCEPTANCE_CRITERIA_DRAFT.md` และตารางผลทดสอบในบทความ

## 5. ข้อจำกัดของการตรวจรอบนี้

- ไม่ได้เปิดเบราว์เซอร์จริง ข้อสรุปด้าน UI ทั้งหมดมาจากโค้ด
- ข้อมูลใน DB จริงมีน้อยและมีทีมเดียว จึงพิสูจน์กรณีข้ามทีมและกรณีข้อมูลมากไม่ได้
- ไม่ได้ตรวจ `vendor/` (ไม่ได้ใช้) และไม่ได้ตรวจรายละเอียดสไตล์ใน CSS
- ข้อสรุปเกี่ยวกับความต้องการของผู้ใช้อิงจากบทความวิจัยและโค้ดเท่านั้น ยังไม่มีข้อมูลจากผู้ใช้จริง
